# Bounded outdoor presentation

The previous scenery cache kept its bitmap buffers small, but its displayed overview canvas and live SVG still had grounds-sized CSS boxes. Chromium's actual layer report showed both at 25,827 by 16,662 CSS pixels. Small backing buffers alone did not bound compositing and overlap work.

`OutsideRaster` keeps the grounds overview and inactive crop history off DOM. The active original DPR sharp crop is displayed directly inside a viewport-sized, clipped inverse camera plane. Its pixel buffer and displayed box cover at most the viewport plus 256 CSS pixels on each side. Panning within that overscan moves its compositor position without copying the entire viewport through two canvases every camera frame. The overview fallback uses the same bounded overscan and refreshes only when its coverage runs out. The original grounds clip, night tint ordering, park placement and CSS variable inheritance remain intact.

The same live SVG remains connected to its existing ambient observers and animation clocks. Its original-vector viewBox includes the same bounded overscan. Camera movement translates that retained viewport instead of changing its viewBox every frame. Coverage or density changes update it immediately. No animation reset, tiled image seam, simplified artwork or quality reduction is introduced. Source replacement snapshots the previous displayed bitmap while the new source decodes.

Sharp raster crops retain the existing screen-density generation, overscan, two-entry history, asynchronous installation and stale-job protection. `data-source-density` and `data-sharp` on the detail display expose the actual installed source's density/coverage for runtime tests. A viewport-sized output buffer by itself is no longer sufficient proof of sharp source content.

`node scripts/verify-outside-viewport.mjs` verifies fractional camera alignment from 0.02x through 6x, clipped source mapping, bounded device-resolution overscan, overview pixel budgets, sharp source coverage and cleanup. Two repeated 80-step camera pans retain the exact sharp canvas, perform no overview presentation blits and keep the same live SVG viewBox. Whole-project TypeScript passes. Actual Chromium layer bounds, appearance and frame times are verified by the coordinator's combined runtime run.

The weather sky uses the same retained presentation principle with 128 CSS pixels of overscan per side. Its existing presentation density is unchanged. Camera motion translates the bounded canvas between actual cloud/fog texture updates; precipitation and the original weather clock remain live. The original viewport-derived 1.6 MP density budget still selects the sky's pixel density, and fixed overscan adds bounded storage around it. Precipitation keeps its existing independent 1.6 MP buffer cap. `node scripts/verify-weather-retention.mjs` checks density, mapping, coverage, edge renewal, continued sky updates and resize cleanup. `render-viewport-checks.cjs` checks actual native sky mapping and those separate buffer bounds.

Middle-button camera input is claimed in the scene's capture phase and explicitly captured to that scene. Workstation controls do not receive the same middle-down or held move events. Matching pointer release/cancel, capture loss, window blur, hidden-document transitions and missed-button-release recovery clear pan state. Ordinary left workstation clicks keep their existing event path. `render-camera-checks.cjs` supplies coordinated native middle-drag, reuse and cancellation checks.

Camera input bursts coalesce into one commit on the display's next animation frame. Removing the independent 60 Hz deadline preserves even input presentation on high-refresh displays. `node scripts/verify-camera-queue.mjs` exercises the actual queue methods with 200-event bursts and 144 Hz timestamps, checking the newest input, one pending callback, focus bookkeeping and no idle animation-frame loop.
